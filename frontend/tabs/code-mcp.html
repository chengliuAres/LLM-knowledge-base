🤖 Agent 接入

MCP (Model Context Protocol) 是 AI 助手与外部工具之间的开放标准协议。连接后，Claude Code、Cursor 等 AI 工具可以直接搜索代码、追踪调用链、进行 RAG 问答。

📡 服务连接信息

服务地址 —
MCP 端点 /mcp/
传输协议 Streamable HTTP
SDK 版本 mcp SDK v1.x
旧端点 (兼容) /mcp/sse

🛠️ 可用工具（5个）

code_search — 混合搜索代码，支持中文查询
code_chat — RAG 代码问答
code_trace — 调用链追踪 (callers/callees)
code_file_context — 获取文件内容
code_list_repos — 列出已索引仓库

🔍 搜索代码
"搜索邮件发送相关的代码"
→ code_search(query="邮件发送", repo="mailflutter")
→ 返回 SendMailPage, MailService 等结果
💬 代码问答
"这段邮件发送逻辑是怎么工作的？"
→ code_chat(question="...", repo="mailflutter")
→ RAG 检索 → LLM 解释，返回来源引用
🔗 调用链追踪
"谁调用了 sendMail？它又调用了谁？"
→ code_trace(symbol="sendMail", direction="both")
→ BFS 多跳，返回调用图 + 被调用图
📄 浏览文件
"帮我看下 login_page.dart 的代码"
→ code_file_context(repo="ghmail", file_name="login_page.dart")
→ 返回 LoginView 类完整内容
⚡ 核心策略
用户提问 → 触发决策（搜索定位/使用调查/影响分析/参考借鉴/追溯调查） → 阶段 1 同步多 query 并行搜 → 阶段 2 后台补全文+调用链 → 喂 LLM 整理答案
🚀 阶段 1：多 query 并行（零后端改动）
AI 一次性发出 2-3 个 search_code，全部 run_in_background=true，后端不用动：
run_in_background(true): code_search(query="会员 member VIP subscribe", repo=xxx) run_in_background(true): code_search(query="CloudMember privilege 续费", repo=xxx) run_in_background(true): code_search(query="membership plus payment", repo=xxx) # 三个返回后 AI 合并去重，总耗时 ≈ 单查询耗时
❌ 错误：串行 search(A) → search(B) → search(C) 三次等结果 = 3 倍单查询时间
📦 阶段 2：后台补全上下文
拿到阶段 1 第一波结果就展示给用户，不阻塞。后台继续：
  • • code_file_context 拉阶段 1 命中文件完整内容（补全 top_k=10 截断）
  • • code_trace 补充调用链（BFS 多跳，深度 1-3）
  • • grep 在命中文件上精确深挖（行级匹配）
⚠️ 反直觉：本地有代码也要先 code_search（语义发现），再 grep（精确深挖）
🚫 反模式（AI 别这样干）
  • ❌ 不要一开始就 grep：grep 只会字面匹配，漏语义相关代码。例："读信顶部引导条" grep→0，code_search→ConversationGuideBar
  • ❌ 已确定文件+行号的修改：直接改，不要搜索
  • ❌ 纯写代码不需要搜索：无"找/参考"意图不触发（除非追加"先看看现有的"）
  • ❌ 通用框架问题：查官方文档，不搜索代码库（"UIView 怎么用"→ 不需要）
  • ❌ 不要串行搜多次同一个 repo：2-3 组 query 并行搜（用 run_in_background）
  • ❌ 不要猜测文件路径：先用 code_search 确认
  • ❌ 不要用中文做精确类名搜索：中文→code_search 语义发现（翻译层负责中→英）
🔄 双模调用（MCP 不可用时降级）
MCP 不可用时**同时做两件事**：
# 1. 立即用模式 B（不阻塞） python3 export/skill/scripts/kb_api.py search --query "XX" --top_k 5 python3 export/skill/scripts/kb_api.py trace --symbol XX --direction both --depth 2 python3 export/skill/scripts/kb_api.py file --repo --path "src/main.py" python3 export/skill/scripts/kb_api.py repos # 2. 引导用户 4 步配置 MCP（不阻塞 AI 工作） # Step 1: Location = Project / User # Step 2: Name = code-kb # Step 3: Type = HTTP # Step 4: URL = http://:8000/mcp/
⚠️ kb_api.py 零依赖（urllib + json + argparse），Python 3.9+ 直接跑
🛟 失败回退链（7 步，code_search 返回空时依次尝试）
  1. 1. code_list_repos 确认仓库在线状态
  2. 2. 去掉 repo 参数（搜所有已索引仓库；当前单仓下等同于搜 ghmail）
  3. 3. 换 query 策略：中文↔英文 / 同义词链（"登录"→"sign in"→"auth"）
  4. 4. 缩短 query："邮件附件下载进度条"→"附件下载"
  5. 5. 加 repo 参数限定（缩小范围确认问题在哪）
  6. 6. grep 在关键路径做字面匹配兜底
  7. 7. 提示用户：可能需要等待索引同步
⚠️ 假阳性：code_search 极少真返回 0 条，更常见是返回"语义相似"等低置信度假阳性。看每条结果的 match_reason 字段判真伪（符号匹配 > 混合匹配 > 关键词匹配 > 语义相似）
