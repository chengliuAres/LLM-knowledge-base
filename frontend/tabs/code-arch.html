B.5 关键代码引用

以下为示意代码（结构对应 code_search.py 实际入口，非逐字拷贝）：

# 真实入口 search_code(mode='hybrid')，见 code_search.py:320
def search_code(query, mode="hybrid", top_k=20, repo_name=None, language=None):
    # 翻译
    keywords = query_translator.translate(query)  # 走 B.3 降级链
    # 顶层 3 路召回
    vec_results = code_db.vector_search(keywords, top_k)        # 顶层 1
    kw_results  = _keyword_search_dual(keywords, query)        # 顶层 2（EN+CN 子双路）
    like_results = code_db.symbol_like(keywords)                 # 顶层 3
    # 顶层 RRF 融合（权重 [1.0, 0.5, 1.5]）
    fused = rrf_fusion(
        [vec_results, kw_results, like_results],
        weights=[1.0, 0.5, 1.5],
        k=60,
    )
    return fused[:top_k]

🧠 D. 设计决策 — 为什么这么做

5 个核心设计决策（实验验证），均来自 2026-06-10 搜索准确率实验。每个决策附带反例故事，来自柳哥的实际报修记录。

D.1 5 个核心决策

决策 结论 证据
跨语言 embedding（e5/bge-m3）代替翻译层 ❌ 中文 query → 纯英文 OC 代码召回接近随机，跨语言桥训练于平行语料非代码
词典是第一道防线 ✅ "读信"→read/mail/message 命中 ReadCell.m；缺词典降级 MyMemory 译成 letter/reading 翻车
embedding 前剥离注释/中文字面量 ✅ 注释/NSString 中的中文会误导 bge 模型，剥离后向量路不再偏到中文噪声
MyMemory 翻译不写入缓存/词典 ✅ MyMemory 直译（"读信"→letter）置信度低且脱离代码命名习惯，写缓存会永久污染
向量阈值 0.0 → 0.5 ✅ score = (1+余弦相似度)/2，0.5=正交分界，砍掉"最近邻但无关"的噪声
D.2 反例：跨语言 embedding 翻车（e5 中文 → 英文 OC 代码）

实测 e5 中文 query → 英文 OC 代码 top-5 命中 UITableView / UICollection 等基础类（语义沾边但符号名完全无关）。

原因：跨语言桥训练于 XNLI / Bucc 等平行语料，不是代码语料，所以代码命名（驼峰/蛇形）不在向量空间内有意义映射。

正确方案：翻译层（词典 + 缓存 + API + LLM）+ 同语言 embedding（bge-small-en）。

D.3 反例：词典缺位翻车（"读信" → letter/reading）

2026-06-12 报"读信" → MyMemory 直译 letter/reading → 符号路 LIKE %letter% 命中 letter.png 资源文件、零业务方法。

修复：在 query_translator.py:45 TERM_MAP 加 读信 → read/mail/message 后，直接命中 ReadCell.m / MailBoxViewController.m。

D.4 反例：中文注释污染 embedding（NSString 字面量干扰 bge 模型）

发现向量路 top-3 总偏向带中文 NSString 字面量的 chunk（如 NSLog(@"读取附件失败...")），因为 bge-zh 残留能力让模型对中文字面量有"亲和力"。

修复：embedder 预处理时正则 re.sub(r'[一-龥]+', ' ', text) 剥离中文。

D.5 反例：MyMemory 缓存污染（错误翻译永久驻留缓存）

早期版本 MyMemory 翻译结果直接写 translation_cache.json，导致后来词典完善后旧 cache 仍优先命中 letter/reading 等错误翻译。

修复：translation_cache.set() 拒收 MyMemory 来源（source != 'mymemory' 才允许写入）。

D.6 额外：向量阈值过松噪声（score > 0.0 引入正交无关代码）

早期 score > 0.0 全部保留，top-10 经常出现"最近邻但正交"的无关代码（如搜 read → release/dealloc）。

修复：阈值 0.5 = (1 + 0) / 2 正交分界，砍掉负相关噪声。
